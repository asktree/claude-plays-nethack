## Shift 1 (local p2, seed 202)
- #491 `threat('goblin')` returned "dangerous" for a lvl-0 1d4-weapon monster at XL1/16 HP, while `threat('jackal')` (#636) is "trivial". Looks like weapon attacks are scored with a large worst-case; made me spend an extra `mon()` call to sanity-check. Expected "trivial"/"normal".
- #1066–#1078 shop price walk with `m`-prefixed steps: no "You see here ... (for sale, N zorkmids)" line was produced (no look-here with the m prefix) and, separately, calling `look()` right after `do()` cleared `obs.messages`, so the whole walk yielded nothing (1 wasted call). Plain steps + reading `obs.messages` immediately after `do()` worked (#1096+). Suggest documenting both in PLAYER.md (or have `look()` keep the last step's messages).
- #1090 the sell prompt text was captured as "Sell i t? [ynaq]" (line-wrapped prompt joined with a space), so a `'Sell it' in prompt` check failed. Suggest normalising whitespace in `obs.prompt` (collapse the wrap) — the raw prompt is "...ANDOVA BEGARIN.  Sell it? [ynaq] (y)".
- #1054 explore() hit the exec budget (400 steps / 21s) mid-target-selection and left the game in a `[getpos]` travel prompt when it paused; `cont` recovered fine, but a pause inside a getpos is fragile if the player sends a plain command next. Expected: budget pause only at a `[command]` state.
- #1252/#1256 `travel(56,5)` and even a waypoint `travel(56,12)` raised NavError "did not move; A boulder blocks your path": NetHack's `_` routes through the boulder at (46,9) (it treats boulders as pushable) and then refuses in run mode. The NE room was reachable via the row-6 door (54,6). travel() could detect "A boulder blocks your path" and retry via an intermediate waypoint that avoids boulder squares, or mention the boulder in the error.
- explore() does not collect items it walks past (gold at (29,9)/(6,18) on D1, (56,5) on D2 were left; `$` autopickup only fires when the path crosses the square). Fine as design, but worth a line in PLAYER.md: after `explored`, sweep `obs.objects`.
- `travel()` to a square where gold lies: the autopickup message is not in `obs.messages` afterwards (empty list), only the `$` counter changes — make sure `obs.status.gold` is the thing to check.
- #1279 arriving on a new level (Mines 1) `obs.under` was None and `obs.features` empty although I stood on the up staircase (`here()` confirmed it); a guard on `obs.under == '<'` refused `<` and cost a call. Expected the staircase under the hero to be listed right after the level change.
- #1288 `travel(74,17)` raised NavError "did not move; That door is closed." at (27,13): NetHack's `_` routes through closed doors and stops next to them. travel() could open the door and continue (or kick if locked), like explore() does, instead of failing. Also the harness `avoid()` marks did not keep `_` from choosing the door+boulder corridor (the game's own pathing ignores them); waypoints were needed.
- #1332 SAFETY: kicking (`<C-d>` + `k`) at a box square the kitten had just stepped onto produced NetHack's getlin "Really attack the kitten? (yes) [no]"; my script then called `inventory()`, which sent `i` straight into that text prompt (screen showed "... [no] i"). Helpers that send keys (`inventory()`, `here()`, `look`-type commands) should refuse/raise when `obs.kind` is not `command`, exactly like the guard on answering "Really attack". Also worth a guard: a directional kick/throw/zap into a square holding a pet/peaceful. Recovery took two `<Esc>` (#1333 still showed the prompt as `[yn]` after the first Esc; #1334 clean).
- #1350 `#loot` "Do what with the large box?" is a pick-one menu: sending `o<CR>` selects "take out" with `o` and the extra `<CR>` then confirms an EMPTY selection in the following "Take out what?" menu, so nothing was taken (had to loot again, #1359). PLAYER.md's menu advice ("letters then <CR>") doesn't hold for pick-one menus; worth a note or a `loot_all()` helper.
- #1371 `engrave_test('o')` paused on "new monster: jackal" in the middle of its own sequence (the wand of create monster created it); after the pause the wand was already identified and the script state was fine, but the helper's return value was lost — printing the verdict via `history` was needed.
- Kittens carry items around constantly ("picks up / drops" every few turns); the harness's `objects` list changes under scripts that target a square — a `travel()` to an object square should re-check the object is still there.
- Corpses carried in inventory rot away ("Your acid blob corpse rots away", T:1053) — `corpse()` could mention the ~250-turn inventory lifetime when advising to carry one.
